# SaaS KPI Analytics

A mini analytics project for a subscription (SaaS) business: customer data from a CRM and invoices from a billing system are loaded into a Snowflake data warehouse, reconciled with SQL, turned into SaaS KPIs (MRR, ARR, churn, NRR, GRR) and prepared for a Power BI dashboard.

> **All data is synthetic.** It is generated by `generate_data.py` with a fixed random seed, so the results are reproducible. The business (a SaaS provider for the construction industry), the customers and the prices are fictional.

## The business case

A software provider sells monthly subscriptions to construction companies in Germany, Austria and Switzerland. Customers are kept in a CRM, invoices come from a separate billing system, and Swiss customers pay in CHF. The questions:

- How much recurring revenue (MRR/ARR) do we have, and how does it move each month?
- Do the CRM and the billing system agree?
- How many customers do we keep and grow (NRR, GRR)?

## The data

| Table | Rows | Content |
|---|---|---|
| `CRM_CUSTOMERS` | 500 | Customer master data like in a CRM: country, trade, sales team, plan, status, MRR |
| `BILLING_INVOICES` | 6,178 | One invoice per customer and month, in local currency |
| `FX_RATES` | 42 | Monthly CHF to EUR exchange rates |

Period: January 2025 to September 2026. Customers: 425 active and 75 churned. Countries: Germany 351, Austria 69, Switzerland 80. Three plans (Basis 89 EUR, Regional 149 EUR, Bundesweit 299 EUR per month, with CHF prices for Switzerland). `CUSTOMER_ID` links CRM and billing (one to many); exchange rates are joined by currency and month.

Result for September 2026: **64,229.50 EUR MRR**, **about 770,800 EUR ARR** (MRR x 12) and **425 active customers**.

## Snowflake and SQL

| File | Content |
|---|---|
| [sql/01_setup.sql](sql/01_setup.sql) | Creates the database `SAAS_DEMO` with the schemas `RAW` (data as it comes from the source systems) and `ANALYTICS` (cleaned data and KPI views) |
| [sql/02_analytics.sql](sql/02_analytics.sql) | Cleaning, reconciliation and KPI views |

The views in `02_analytics.sql`:

| View | What it does |
|---|---|
| `CUSTOMERS_CLEAN` | CRM without duplicates, one row per customer (`QUALIFY ROW_NUMBER()`) |
| `RECON_CRM_VS_BILLING` | Finds where CRM and billing disagree: invoiced but missing in CRM, duplicate CRM record, active but not invoiced, churned but still invoiced, MRR differs from the billed amount |
| `MRR_MONTHLY` | Monthly revenue per customer, converted to EUR |
| `MRR_MOVEMENTS` | Classifies every customer and month as New, Expansion, Contraction, Churn or Retained. It uses the local amount, so exchange-rate changes do not look like upsell |
| `KPI_MONTHLY` | MRR, ARR, active customers, new and churned customers and MRR movements by month, country and sales team |
| `NRR_12M` | Net and gross revenue retention: revenue today from the customers that existed 12 months ago |

SQL techniques used: JOINs, CTEs, `CASE`, window functions (`ROW_NUMBER`, `LAG`, `PARTITION BY`), `QUALIFY`, `FULL OUTER JOIN` and `CROSS JOIN` for a customer-month grid. The scripts use Snowflake syntax.

## Power BI

The deck describes a Power BI dashboard on top of the Snowflake views, with a one-to-many data model, DAX measures (`LOOKUPVALUE` for the CHF to EUR conversion, `CALCULATE`, `VAR`, `DISTINCTCOUNT`), KPI cards, an MRR trend, MRR by country and a filter by sales team. The `.pbix` file is not included in this repository.

## Run it

```bash
pip install -r requirements.txt
python generate_data.py   # writes the CSV files to data/
python make_excel.py      # writes saas_kpi_data.xlsx
```

To use the SQL, create the schema with `sql/01_setup.sql` in Snowflake, upload the three CSV files into `SAAS_DEMO.RAW`, then run `sql/02_analytics.sql`.
